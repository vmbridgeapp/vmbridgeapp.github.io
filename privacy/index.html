VMBridge / Privacy policy

Privacy policy

VMBridge runs on your Mac and talks to virtual machines that Parallels Desktop is already running. This page describes that local app. It is not a promise about Parallels Desktop's own privacy policy.

No analytics SDK

The app does not include an analytics product, a telemetry pipeline, or a crash reporter such as Sentry. Pages on this website are static files. They do not set a cookie and they do not load a third-party script.

What stays on the Mac

  • Trial state is stored in the login Keychain (service "VMBridge license") and in a license file under ~/Library/Application Support/VMBridge. An older "Parallels Pro MCP" folder is reused when it is the only copy, so the trial clock is not reset by the rename.
  • A guest sign-in password is stored in the login Keychain under "VMBridge sign-in". Tools do not return that password. The activity log records that a sign-in ran, not the secret.
  • The activity log records tool calls. Typed text and passwords are not written into it.
  • Files an agent sends to the Mac land in ~/Downloads/From VMs.

What is sent off the Mac

Activating, validating, or deactivating a license key sends the key and an instance name to the Lemon Squeezy License API at api.lemonsqueezy.com. The app does not ship a store API secret. A key is accepted only when its store id and product id match VMBridge. The website buy button opens that checkout. The store is in test mode pending approval.

Creating a Linux or macOS guest can download an image from the distribution's own publisher, or an IPSW from Apple, because that is how vm_create obtains install media. That download is the guest image, not a VMBridge account.

Inside a virtual machine

An agent running inside a guest uses a token that the daemon accepts only from that VM's addresses. The daemon listens on 127.0.0.1 and on the Parallels Shared and Host-Only networks. It does not listen on every interface unless you set that bind address yourself.

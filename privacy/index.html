VMBridge / Privacy policy

Privacy policy

VMBridge runs on your Mac and talks to virtual machines that Parallels Desktop is already running. This page describes that local app. It is not a promise about Parallels Desktop's own privacy policy.

No analytics SDK

The app does not include an analytics product, a telemetry pipeline, or a crash reporter such as Sentry. Pages on this website are static files. They do not set a cookie and they do not load a third-party script.

What stays on the Mac

  • Trial state is stored in a license file under ~/Library/Application Support/VMBridge. On first launch an older Application Support folder is moved there, including the license file, so the trial clock is not reset. If that move fails, the older folder is still used.
  • A guest sign-in password is stored in a private file in that same folder. Tools do not return that password. The activity log records that a sign-in ran, not the secret.
  • The activity log records tool calls. Typed text and passwords are not written into it.
  • Files an agent sends to the Mac land in ~/Downloads/From VMs.

What is sent off the Mac

Activating, validating, or deactivating a license key sends a request to api.polar.sh, run by Polar, the merchant of record. The request contains the license key, the Polar organization id, and either an activation id or a label for the Mac. On first activation the label is the product name, a name for the Mac, and the first 8 characters of a random id VMBridge creates when first run. The Mac app uses the computer name from Sharing settings, which often includes the owner's name, for example "VMBridge (Jane's MacBook Pro/abcdefgh)". If no computer name is set, it uses the hostname. The command-line tool uses the Mac's hostname. Later checks send the key with the activation id, or with that label or the product name when no activation id is stored. The app does not ship an API token. A key is accepted only when its organization id matches VMBridge.

The Buy button in the app and on the website opens Polar's checkout page in your browser. The app does not send your license key to the checkout.

Creating a Linux or macOS guest can download an install image from the distribution's publisher (releases.ubuntu.com, cdimage.ubuntu.com, fedoraproject.org, download.fedoraproject.org, cdimage.debian.org, or cdimage.kali.org, and the mirrors those publishers redirect to) or an IPSW from Apple (mesu.apple.com and Apple's download servers), because that is how vm_create obtains install media. That download is the guest image, not a VMBridge account.

A build that includes automatic updates checks the VMBridge update feed and downloads the signed update from it. A build without automatic updates does not make those requests.

Inside a virtual machine

An agent running inside a guest uses a token that the daemon accepts only from that VM's addresses. The daemon listens on 127.0.0.1 and on the Parallels Shared and Host-Only networks. It does not listen on every interface unless you set that bind address yourself.

VMBridge feature comparison

VMBridge exposes Parallels Desktop virtual machines to AI agents over MCP.

VMBridge brings agent access to virtual machines you already run in Parallels Desktop. Its MCP server gives an agent a whole computer using Parallels' own SDK and CLI.

What is the core agent workflow?

  • An MCP server the agent can add in one step, including Claude Code, Codex, Cursor, and others.
  • The agent sees the display and can click, type, scroll, and drag.
  • Commands as the user or as admin, file copy, snapshots, and a stored sign-in password the agent does not receive.
  • Per-VM permission to let an agent control that VM, and a global switch for creating and deleting VMs.

How does VMBridge differ from dedicated hypervisors?

  • VMBridge is not a hypervisor. Parallels Desktop starts the VM, provides the disk format, and owns USB, graphics, and the guest OS installers.
  • VMBridge can focus a window, open an app or URL, search files by name, report the pointer after it moved it, pause the guest, and read its own activity log. Those tools were added because an agent driving a VM asks for them.
  • VMBridge does not record the screen as video. It returns still frames. A burst of images would fill the disk.
  • VMBridge uses macOS Vision OCR for text targets on screen.
  • Snapshot rename is not available because prlctl has no rename command.

Which one is this page about?

This page is about VMBridge. It is a factual overview so you can see how VMBridge provides agent VM capabilities on top of Parallels Desktop.

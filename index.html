What the agent can actually call

Screen and input

vm_screenshot (with a region zoom), vm_read_screen OCR, click, click text, type, key, scroll, drag, and mouse. vm_cursor reports the pointer only after this server moved it. vm_act batches steps. vm_wait waits for text, for text to leave, or for the screen to change. Input goes through the Parallels Virtualization SDK, so the Mac does not ask for Accessibility or Screen Recording permission. Screen and input work without Parallels Tools, including while an installer is on screen. Keystrokes use US key positions; other text should use paste, which needs Tools.

Commands and files

vm_run is a shell line. vm_exec is an exact argv. Admin is a separate allow. Background jobs are vm_job_status, vm_job_stop, and vm_job_list. Read, write, and list files; copy to and from the guest; vm_send_to_mac lands in ~/Downloads/From VMs. vm_windows lists and focuses windows (Linux needs wmctrl). vm_open launches a quoted app or URL, not a shell command. vm_find_files matches file names, six folders deep, at most 200 paths, and is not a full-text search. On Windows, guest commands run as SYSTEM.

Virtual machines

Start, stop, suspend, pause, resume, and restart. vm_create with vm_systems covers Ubuntu, Fedora, Debian, Kali, and macOS IPSW images. Windows is created with the Parallels assistant or an ISO; the agent can drive the installer. There is no unattended installer. vm_run_ephemeral copies a VM, runs, and deletes the copy. Snapshots: snapshot_create, snapshot_revert, snapshot_delete, snapshot_list. There is no rename. vm_sign_in types a stored password the agent never receives. Also: configure, shared folders, port forward, headless, autostart, delete to the Trash, status, list, install Tools, and the activity log.

Safety

Each VM has its own agent-control switch. Creating, cloning, and deleting VMs need a global manage-all switch that is off by default, and the agent is asked to confirm the first time. Pause all agents stops every call. The activity log does not store typed secrets. An agent inside a VM gets an HTTP token that is accepted only from that VM's addresses. A clone cannot reuse it.

What it does not do

  • It does not record video of the VM. Screenshots are still frames.
  • It does not read the guest accessibility tree. On-screen text is OCR.
  • It does not rename snapshots. prlctl has no rename command.
  • It does not pass through USB, and it does not install a guest unattended.
  • It is not a hypervisor. Parallels Desktop runs the VM.

Common questions

What is VMBridge?

VMBridge is a macOS app for Parallels Desktop. It gives an AI agent a virtual machine as its own computer over MCP: screen, keyboard, mouse, commands, files, and snapshots. The price is $9.99 one-time, 7-day free trial. The trial is full-featured.

Does VMBridge replace Parallels Desktop?

No. VMBridge drives virtual machines that Parallels Desktop already runs. You need Parallels Desktop Pro or Business on the Mac. Parallels is a trademark of Parallels International GmbH. VMBridge is not affiliated with Parallels.

How does Claude Code control a VM?

Run vmbridge connect claude-code on the Mac. Claude Code then talks to the VMBridge MCP server. The agent sees the guest screen and uses the guest keyboard and mouse. It does not drive your Mac desktop.
